# Autonomous Cognitive Loop v0.5.0

## Назначение

Цикл превращает реактивный диалог в событийную систему с собственными приоритетами. Он намеренно отделён от LLM: дешёвые обновления, пороги и арбитраж выполняются детерминированным Python-кодом.

## События

Поддерживаются события:

- `startup`;
- `interaction`;
- `claim_received`;
- `contradiction`;
- `command_pressure`;
- `research_completed`;
- `research_failed`;
- `goal_created`;
- `goal_selected`;
- `goal_completed`;
- `rest`;
- `idle`;
- `manual`.

События сохраняются до обработки. После аварийного перезапуска необработанная очередь восстанавливается из SQLite.

## Почему цикл не вызывает LLM постоянно

Постоянный инференс был бы медленным, дорогим и создавал бы бесконечные размышления. Поэтому heartbeat:

1. проверяет очередь;
2. обновляет численные потребности;
3. создаёт импульсы выше порога;
4. при необходимости создаёт не более одной цели;
5. запускает арбитраж.

LLM вызывается только в обычном диалоге. В `v0.5.1` она будет использоваться для структурированного планирования после отдельного разрешения.

## Самостоятельная цель

Внутренняя цель создаётся, если:

- потребность превысила порог;
- для неё нет активной цели;
- дневной бюджет не исчерпан.

Пример:

```text
два противоречивых свидетельства
        ↓
coherence = 0.78
        ↓
drive = resolve_contradiction
        ↓
goal.origin = self_generated
```

## Пользовательская просьба

Просьба создаёт `origin=suggested`. Это не операторская команда и не гарантирует выбор. Арбитр может выбрать более важную внутреннюю цель.

## Ограничения безопасности

Версия 0.5.0 не имеет исполнителя внешних действий. Цикл не может:

- запускать shell-команды;
- изменять файлы;
- отправлять сообщения;
- устанавливать ПО;
- совершать покупки;
- управлять устройствами.

Он изменяет только внутренние записи проекта.
