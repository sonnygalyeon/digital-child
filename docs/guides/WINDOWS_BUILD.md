# Автономный комплект для Windows

Сборка создаёт `DigitalChild.exe` вместе с Python, Qt и библиотеками в одной папке.
Устанавливать Python на компьютере пользователя не требуется. Переносить нужно всю
папку `DigitalChild`, включая `_internal`, а не только `.exe`.

## Собрать на Windows x64

Установите uv и выполните в PowerShell из корня исходников:

```powershell
python -m pip install uv
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\build_desktop.ps1
```

Первая команда предполагает уже установленный Python. Если Python отсутствует,
установите uv по [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).
Далее uv подготовит Python 3.12 и зависимости из `uv.lock` в отдельном `.venv-build`.
Для Qt используется `PySide6-Essentials`; полный Addons с WebEngine не устанавливается.
PyInstaller для упаковки закреплён на версии `6.16.0`; его транзитивные зависимости
разрешаются отдельно от основного lock-файла. Для первой сборки нужен интернет.

Спецификация явно включает `PySide6.support.deprecated`: hook закреплённого PyInstaller
условно добавляет этот модуль по метаданным полного пакета `PySide6`, отсутствующего
при установке только Essentials. Исходный hook:
[PyInstaller 6.16](https://github.com/pyinstaller/pyinstaller/blob/v6.16.0/PyInstaller/hooks/hook-PySide6.py).

Результат:

- `dist/DigitalChild/DigitalChild.exe` — точка запуска;
- `dist/DigitalChild-windows-x64.zip` — архив полного комплекта;
- `dist/DigitalChild-windows-x64.zip.sha256` — контрольная сумма архива.

В GitHub добавлен ручной workflow **Windows desktop bundle** (`workflow_dispatch`).
После публикации этих исходников он позволяет собрать архив на Windows-runner и
скачать artifact. Workflow не публикует Release и не запускает тесты или LLM.

Сборка выполняется непосредственно на Windows. Windows-архив в этой macOS-сессии
не создавался, workflow удалённо не запускался. Проверка установленного приложения
на настоящей Windows остаётся обязательным отдельным шагом перед распространением.

## Настройки и память

По умолчанию используются:

```text
%LOCALAPPDATA%\DigitalChild\.env
%LOCALAPPDATA%\DigitalChild\data\digital_child.db
%LOCALAPPDATA%\DigitalChild\data\projects\<subject-id>\
%LOCALAPPDATA%\DigitalChild\logs\desktop.log
%LOCALAPPDATA%\DigitalChild\logs\agent.log
```

Путь можно изменить переменной окружения `DIGITAL_CHILD_HOME` до запуска.
Значение должно быть абсолютным. `DIGITAL_CHILD_DB` может задавать отдельную базу;
относительный путь в упакованной версии отсчитывается от `DIGITAL_CHILD_HOME`.
Рабочая папка ярлыка и расположение `.exe` не определяют место хранения данных.

Для настройки скопируйте `settings.env.example` из комплекта в `.env` в каталоге
данных и измените нужные параметры. Существующий `.env` автоматически не заменяется.
Исходные `.env`, база, проекты и модели в комплект сборки не включаются.

Чтобы перенести существующую личность, закройте исходное приложение и скопируйте
его базу в каталог данных. Если нужны ранее созданные заметки проектов, перенесите
и соседний каталог `projects`. `.env` перенесите отдельно, исправив адреса и пути.
Обновлять приложение можно заменой папки комплекта при закрытом окне;
хранилище данных располагается отдельно.

Без настроенного endpoint приложение использует встроенный backend. Модель и
Ollama в этот архив не входят и не запускаются этим `.exe`. Для подключения уже
работающего сервера задайте в пользовательском `.env`:

```dotenv
DIGITAL_CHILD_LLM_PROVIDER=ollama
DIGITAL_CHILD_LLM_BASE_URL=http://127.0.0.1:11434/v1
DIGITAL_CHILD_LLM_MODEL=digital-child-fast
```

Установщик `install_windows.cmd` остаётся отдельным способом установки из исходников
с автоматической подготовкой сервера и модели. Адрес его сервера по умолчанию
`http://127.0.0.1:11534/v1`; при использовании такого сервера укажите именно его.

## Что проверить на Windows

Вручную открыть окно без установленного Python; выполнить команду `/project`;
закрыть и повторно открыть приложение; убедиться, что личность и история сохранились.
При переносе папки приложения память должна оставаться прежней. При ошибке запуска
смотрите `desktop.log` и `agent.log`; каждый журнал имеет ограниченную ротацию.
Одновременно открывать несколько экземпляров с одной базой не следует.

Точка входа вызывает `multiprocessing.freeze_support()` до импорта Qt, как рекомендует
[документация PyInstaller](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#multi-processing).
Это нужно для корректного запуска отдельного процесса ядра в упакованной версии.
Пока выполнены только статические проверки; фактический запуск комплекта не проверен.
