# Оконный Digital Child

## Запуск

```bash
uv sync --extra desktop
uv run digital-child desktop
```

Desktop-extra использует `PySide6-Essentials`. Он предоставляет необходимые
QtCore, QtGui и QtWidgets под тем же пространством имён `PySide6`.
Полный пакет `PySide6` и его Addons отдельно устанавливать не требуется.

Дополнительные параметры:

```bash
uv run digital-child desktop --db data/digital_child.db
uv run digital-child desktop --no-auto-research
uv run digital-child desktop --no-cognitive-loop
```

Путь базы берётся из `--db`, затем `DIGITAL_CHILD_DB` в окружении или `.env`,
затем `data/digital_child.db`. Существующая база мигрируется обычным механизмом ядра.
При открытии восстанавливаются последние 100 сообщений локального собеседника.

## Windows

Для чистой Windows предварительная установка утилит не нужна:

1. Скачайте [ZIP ветки](https://github.com/sonnygalyeon/digital-child/archive/refs/heads/developmental-psychology-windows.zip).
2. Распакуйте его и запустите `install_windows.cmd`.
3. Укажите каталог приложения и отдельный каталог хранения моделей.
4. Дождитесь установки и открытия окна. Последующие запуски — ярлыком **Digital Child**.

Полная инструкция: [WINDOWS_CLEAN_INSTALL.md](WINDOWS_CLEAN_INSTALL.md).
Модель устанавливается автоматически; сервер запускается на `127.0.0.1:11534`.
Ярлык поднимает сервер после перезагрузки Windows и открывает окно без терминала.

Ниже сохранена установка для разработчика с уже подготовленным окружением.

Откройте PowerShell в корне проекта. Если `uv` ещё не установлен:

```powershell
winget install --id astral-sh.uv -e
```

После установки `uv` откройте новый PowerShell и выполните:

```powershell
.\scripts\windows\setup_desktop.ps1
```

Если локальная политика Windows запрещает запуск скачанных скриптов, можно запустить
именно этот скрипт отдельным процессом, не изменяя постоянную политику:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\setup_desktop.ps1
```

Установка создаёт `.venv`, устанавливает Qt и создаёт ярлык **Digital Child** на рабочем
столе. Параметр `-NoShortcut` отключает создание ярлыка. Повторная установка сохраняет
существующие `.env` и память. Новый `.env` содержит настройки локальной Ollama с моделью
`digital-child-fast`; саму Ollama и модель этот скрипт не устанавливает.

Ярлык запускает `.venv\Scripts\digital-child-desktop.exe` — GUI entry point Python
без консольного окна. Это запуск из установленного окружения, а не автономный переносимый
`.exe`: каталог проекта и `.venv` должны оставаться на своих местах.

Для автономного комплекта подготовлен отдельный процесс упаковки:
[WINDOWS_BUILD.md](WINDOWS_BUILD.md). Он включает Python и Qt и хранит пользовательские
данные вне папки приложения. Фактическая сборка и запуск такого комплекта на Windows
пока не выполнялись.

Альтернативный запуск:

```powershell
.\scripts\windows\start_desktop.ps1
```

## Подключение модели

Для Ollama на том же Windows-компьютере:

```env
DIGITAL_CHILD_LLM_PROVIDER=ollama
DIGITAL_CHILD_LLM_BASE_URL=http://127.0.0.1:11434/v1
DIGITAL_CHILD_LLM_MODEL=digital-child-fast
```

Имя должно совпадать с реально установленной моделью. Настройка `digital-child-fast`
уже описана в [Windows LLM host](WINDOWS_LLM_HOST.md). Для готового шлюза:

```env
DIGITAL_CHILD_LLM_PROVIDER=openai-compatible
DIGITAL_CHILD_LLM_BASE_URL=http://127.0.0.1:8787/v1
DIGITAL_CHILD_LLM_MODEL=digital-child-fast
DIGITAL_CHILD_LLM_API_KEY=ключ-из-windows_host-env
```

Адрес заменяется на LAN-адрес, если шлюз работает на другом компьютере. Сам агент,
SQLite и интерфейс теперь могут работать полностью на Windows. Windows-host остаётся
необязательным шлюзом для инференса, а не графическим приложением.

Если LLM отключена или недоступна, интерфейс показывает это явно; ядро может отвечать
встроенными правилами. Сфера при этом продолжает отражать эмоциональные параметры.
Команда `/llm` в поле ввода проверяет подключение модели.

## Перенос существующей личности

Закройте все процессы агента на исходном компьютере, затем скопируйте
`data/digital_child.db` в `data` на Windows. Для нестандартного расположения используйте
`DIGITAL_CHILD_DB` или `--db`. `.env` с локальными путями и адресами адаптируйте к Windows.
Запуск не сбрасывает биографию, убеждения, отношения и опыт.

## Диалог и управление

- Enter отправляет сообщение; Shift+Enter добавляет строку.
- Потоковый ответ появляется в карточке агента по мере генерации.
- Поле ввода остаётся доступным для подготовки следующего сообщения; отправка и команды
  недоступны до завершения текущего ответа.
- Кнопки «Память», «Убеждения», «Цели» и «Справка» используют существующий маршрутизатор.
- «Пауза» останавливает фоновый цикл; «Продолжить» возобновляет его.
- «Запустить» включает цикл, если приложение открыто с `--no-cognitive-loop`.
- «Отдых» восстанавливает энергию через `/rest`.
- Все прежние slash-команды поддерживаются, включая `/diagnostics`, `/research`, `/needs`.
- Вкладка «Личность» показывает характер, регуляцию и оценку эффективности.
- `/personality`, `/development`, `/behavior`, `/habits`, `/reflections` открывают
  диагностику индивидуальности, возраста, стратегии и обучения на опыте.
- Размер окна и ширина панелей запоминаются в пользовательских настройках Qt.

Текст сообщения отображается как обычный текст: HTML собеседника или модели не исполняется.

## Сфера

Визуальный ориентир — сферический образ
[Xbox Support Virtual Agent](https://news.xbox.com/en-us/2024/12/13/support-virtual-agent-is-here-to-help/).
Отрисовка собственная, процедурная; ресурсы Xbox и его API не используются.

Сфера состоит из устойчивого светящегося ядра, семи вложенных прозрачных оболочек,
широких световых лент, поверхностных частиц и внешнего свечения. У каждой оболочки
собственная ось и скорость вращения. Это проекция объёмной геометрии в Qt QPainter,
без зависимости от WebView или GPU-движка.

| Состояние ядра агента | Реакция сферы |
| --- | --- |
| Любопытство | движение оболочек и искр активнее |
| Доверие | оболочки расходятся, внешний слой становится открытее |
| Растерянность | ленты деформируются сильнее, согласованность снижается |
| Уверенность | контуры яснее и устойчивее |
| Возбуждение | вращение и пульсация усиливаются |
| Усталость | движения замедляются, свет приглушается |
| Размышление | скорость слоёв возрастает |
| Ответ | дополнительные волны от поступающих текстовых токенов |
| Настороженность / скепсис / радость | меняется эмоциональная палитра |
| Раздражение / тревога | деформации оболочек усиливаются |
| Грусть / привязанность / гордость / скука | отдельные эмоциональные палитры |
| Регуляция | снижает силу деформаций при напряжении |

Переходы сглаживаются экспоненциально с постоянной времени 0,7 секунды. Фаза вращения
накапливается непрерывно: изменение скорости не перескакивает на другой угол.
Процесс ответа меняет движение, сохраняя цвет основной эмоции. Волны ответа привязаны
к текстовым токенам; голосового ввода, TTS и анализа звуковой амплитуды пока нет.

Сфера только отображает состояние. Она не начисляет опыт и не меняет убеждения.
Семь оболочек — визуальные элементы, а не семь отдельных нейросетей.
Психологическая логика описана в [DEVELOPMENTAL_PSYCHOLOGY.md](../features/DEVELOPMENTAL_PSYCHOLOGY.md).

## Разделение процессов

```text
Qt: окно, ввод, переписка, сфера
              ⇅ локальный Pipe
Python: DigitalChildAgent → SQLite / LLM / исследования / когнитивный цикл
```

Ядро стартует через `multiprocessing` / `spawn`, совместимый с Windows. В GUI нет
сетевых вызовов к модели и запросов к базе. Команды обрабатываются последовательно.
Состояние обновляется примерно раз в секунду; токены и уведомления приходят событиями.
Анимационный таймер работает независимо от задержек LLM, с целевой частотой 60 кадров/с.
Фактическая частота зависит от компьютера.

При закрытии окно просит ядро завершиться. Если текущий сетевой вызов не отпускает
процесс за 3 секунды, процесс завершается принудительно. Уже записанные транзакции SQLite
сохраняются; незавершённый ответ может не попасть в историю. Остановка не блокирует Qt.

## Проверки

```bash
uv sync --extra desktop --extra dev
uv run pytest
```

Добавлены проверки динамики сферы, обмена с настоящим дочерним процессом, сохранения
диалога, паузы/возобновления и Qt-окна с вводом Unicode и восстановлением истории.
Qt-проверка использует offscreen-платформу и пропускается, если desktop-extra отсутствует.
Текущая разработка проверена на macOS; запуск установочных скриптов и GUI entry point
необходимо проверить непосредственно на Windows.

Эти проверки относятся к этапу создания интерфейса. Для последующего изменения
психологии тесты не добавлялись и не запускались по запросу пользователя.
