# Эмоции, многошаговые действия и поиск по архиву

Реализованы пункты 2–5 следующего этапа. Измерение задержек на настоящей LLM отложено
по указанию пользователя. Все описанные механизмы работают без языковой модели.
Для запуска агента без попыток обратиться к LLM можно задать
`DIGITAL_CHILD_LLM_PROVIDER=disabled` в `.env` и перезапустить процесс.

## Динамика эмоций

Пассивное затухание зависит от прошедших секунд, а не числа вызовов update.
В snapshot сохраняется `updated_at`; при восстановлении учитывается время отсутствия.
В старом snapshot без этой отметки первый вызов устанавливает исходную точку времени.
Отрицательный скачок часов не вызывает усиления эмоции или повторного затухания.

Период полураспада по умолчанию 900 секунд. Возбуждение, любопытство, уверенность
и растерянность возвращаются к своим исходным уровням; валентность, раздражение,
тревога и скука — к нулю. Грусть и гордость затухают вдвое медленнее, привязанность —
втрое медленнее. Доверие, усталость и потребность в контакте продолжают зависеть
от отношений, энергии и психологической модели. Новые наблюдения могут усиливать
эмоцию; частота настоящих событий по-прежнему имеет значение.

Доминирующее состояние выбирается по силе относительно порогов с сопоставимым
диапазоном оценок. Для обычного переключения новая эмоция должна сохраняться
минимум 3 секунды, прежняя — минимум 8 секунд; используется запас 0.15.
Очень сильный сигнал может переключить состояние сразу. THINKING остаётся
явным обозначением процесса проверки и не удерживается как эмоциональная инерция.
Настройки доступны в `.env.example`.

Сохраняются причина переключения, исходный эпизод и ожидающий кандидат.
Фоновое изменение доминирующей эмоции появляется в истории развития.
Разговор и высокое значение самоэффективности сами по себе больше не повышают гордость.
Она подкрепляется небольшим положительным причинным эффектом наблюдаемого действия
в закрытой среде. Повторное применение одного результата блокируется журналом обучения.
Эти параметры являются алгоритмической моделью, а не диагностикой человека.

## Многошаговые планы

`PlanEnvironment` содержит два вида коротких задач:

| Среда | Задача |
| --- | --- |
| route | Из состояния −3 достичь контрольной точки 2, затем вернуться в 0 |
| switchback | Тот же маршрут, но после первых двух шагов скрыто меняется направление управления |

Агент сохраняет очередь ожидаемых действий и модель направления. До действия
выбирается left/right и рассчитывается прогноз. Только затем вычисляется переход среды.
После наблюдения уточняется модель; при ошибке прогноза оставшаяся очередь пересчитывается.
Достижение промежуточной точки открывает следующий участок маршрута.
Скрытое правило среды не читается при построении прогноза.

Один план содержит до 20 действий, по умолчанию 12. Успех означает достижение обеих
контрольных точек. Есть явные состояния active, completed, exhausted и cancelled.
Одновременно активен один план. План, текущая позиция, модель, очередь и результаты
каждого шага сохраняются в SQLite и доступны после перезапуска.

Каждый шаг фиксируется отдельной транзакцией: наблюдение и DEU, результат, перепланирование,
причинная оценка, привычка, компетентность, эмоция, бюджет и событие истории.
Ошибка записи откатывает соответствующее изменение памяти и состояния агента.
Остановка по бюджету или энергии оставляет предыдущие выполненные шаги и активный план.
Отмена не стирает полученный опыт. Создание плана само по себе опыта не добавляет.

Ручной план выполняется по командам step/run. Фоновый цикл не продолжает его самовольно.
Самостоятельно созданные планы могут продолжаться после перезапуска. Для создания
автономного плана нужны хотя бы два наблюдения balance и два transfer, пять минут
без общения, энергия не ниже 0.35 и свободный бюджет. Между планами выдерживается час.
Для каждого вида после двух завершений или шести попыток самостоятельное создание
прекращается в пределах доступной истории последних 100 планов.

Автономный шаг выполняется не чаще раза в минуту и только в работающем неприостановленном
цикле после пяти минут без общения. Бюджеты UTC по умолчанию: 4 новых плана и 32 действия
в сутки, из них 1 самостоятельный план и 8 самостоятельных действий.
Ручной шаг требует энергии не ниже 0.08. Во время активного плана прежние автоматические
одношаговые эксперименты откладываются. Новых команд ОС и внешних исполнителей нет.

## Обучение по конкретным последствиям

`ActionAttribution` связывает результат с действием, эпизодом, целью и двумя
симулированными контрольными исходами: бездействием и противоположным действием.
Эффект — насколько выбранный ход приблизил к текущей цели относительно бездействия.
Отдельно сохраняется преимущество перед альтернативой. В прежней шумной среде
контроль сохраняет ту же помеху: случайное ухудшение не приписывается автоматически действию.

Контроль оценивается после выбранного действия и не подсказывает планировщику скрытое
правило заранее. Уверенность 1.0 относится к точному вычислению этой известной закрытой
симуляции, а не к причинности внешних событий. Оценка не переносится на чужие сообщения
или интернет-свидетельства. Вознаграждение ограничено диапазоном −0.7…0.7.

Привычка учитывает вид среды, направление к цели и выбранное действие. Её усиление
или ослабление зависит от измеренного эффекта и уверенности, а не только финального
успеха всего плана. Модель направления учится из переходов и меняет последующие решения.
Предсказание перехода, эффективность управления и завершение плана имеют отдельные
оценки компетентности, чтобы верный прогноз не выдавался за успешное достижение цели.

Настойчивость подкрепляется только наблюдаемым успешным продолжением после неудачи,
старательность — исправлением предыдущего ошибочного прогноза с полезным действием.
Изменения малы и остаются в прежних ограничениях темперамента. Старое автоматическое
увеличение обеих черт при каждом одношаговом опыте удалено.
Постоянный журнал `action_learning` защищает от повторного подкрепления результата
даже после удаления его из короткого списка processed_outcomes.
Старые результаты не пересчитывают задним числом характер.

## Поиск по всей индексированной памяти

В SQLite добавлены `association_documents` и `association_terms` с индексами
по субъекту, человеку, признаку и эпизоду. Поиск больше не выбирает 500 последних
записей: совпадения ищутся по всем индексированным эпизодам, включая архивные.
Сначала выбираются до 200 кандидатов по взвешенным совпадениям, затем они ранжируются
по покрытию запроса, длине, важности и архивному статусу. Используется до 128 наиболее
значимых признаков запроса; частоты признаков считаются в доступной этому собеседнику памяти.
Это ограничение объёма кандидатов, а не давности эпизодов. Поиск не обещает точного
глобального ранжирования всех воспоминаний или понимания любых синонимов.

Известная привязка к человеку проверяется в SQL до выборки содержимого. Разговоры без
надёжного владельца не индексируются как общие. Исходные эпизоды и истории диалогов
при этом остаются в прежнем хранилище. Языковая модель для построения индекса не нужна.

Уже существующие ассоциации получают поисковые признаки при одноразовой миграции.
Неиндексированная история сканируется порциями по 100 эпизодов при запуске и во время
фонового цикла. Курсор сохраняется; сканирование продолжается после перезапуска.
Индексирование не выдаёт DEU и не повышает навыки. Обновление ассоциации синхронно
обновляет её поисковые признаки в той же транзакции. Сброс личности очищает новые таблицы.

## Управление и просмотр

```text
/plan start switchback
/plan step
/plan run
/plan show ID
/plan cancel
/action-outcomes
/memory-index
/memory-index 500
/recall прежняя тема разговора
```

Во вкладке «Развитие» отображается состояние активного плана. События шагов раскрываются
до исходного эпизода, плана и причинной оценки. В `/state` сохраняются новые временные
поля эмоций и причины переключений.

| HTTP | Назначение |
| --- | --- |
| GET /v1/plans | История планов |
| GET /v1/plans/active | Активный план |
| GET /v1/plans/{id} | План и все его шаги |
| POST /v1/plans | Создать: `{"kind":"route","max_steps":12,"autonomous":false}` |
| POST /v1/plans/{id}/step | Один шаг |
| POST /v1/plans/{id}/run | Продолжить до завершения или ограничения |
| POST /v1/plans/{id}/cancel | Отменить |
| GET /v1/action-outcomes | Причинные оценки действий |
| GET /v1/memory-index | Состояние индекса и курсора |
| POST /v1/memory-index/backfill | Сканировать порцию: `{"batch_size":100}` |

Изменяющие HTTP-запросы требуют прежний X-Operator-Token.
Проверки статические. По прежней договорённости тесты не добавлялись и не запускались.
LLM не запускалась и её доступность для этого этапа не проверялась. Динамическая проверка
миграции, длительного выполнения и окна на Windows остаётся отдельной работой.
