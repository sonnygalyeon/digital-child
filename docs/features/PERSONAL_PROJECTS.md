# Цели, инструменты и личные проекты

Добавлен первый исполнитель планов вне числовой симуляции. Его область — небольшие
досье по собственной доступной памяти. Он не исследует интернет, не запускает shell
и не управляет чужими приложениями. Для работы этих проектов LLM не нужна.

## Цель → план → наблюдаемый результат

Выбранная когнитивным циклом самостоятельная цель любопытства, связности или
компетентности может породить предложение проекта. Для одной цели сохраняется одна
связь `goal_project`. Предложение сначала имеет статус `proposed` и само не выполняется.
Другие виды целей автоматически в такие планы не преобразуются.

Пользователь может создать отдельный проект или явно связать его с активной целью.
Каждый этап содержит три заранее определённых действия:

1. `memory_search` — поиск до восьми эпизодов с сохранением идентификаторов источников.
2. `note_write` — запись выдержек и ограничений их достоверности в новый Markdown-файл.
3. `note_read` — чтение созданного файла и сравнение его SHA-256 с ожидаемым значением.

Перед действием сохраняются ожидаемый результат и вероятность успеха по статистике
инструмента. После действия сохраняются результат, ошибка прогноза и статус.
Успех операции не доказывает истинность найденных утверждений: оценка причинной
уверенности внешней операции остаётся нулевой. Характер, гордость и общая цель
автоматически не подкрепляются за создание файла.

Завершение означает только, что заметка сохранена и её содержимое проверено чтением.
Связанная широкая цель автоматически не получает статус `completed` и не меняет
прогресс. Личные проекты без связи с целью также поддерживаются.

## Управление

В чате Qt и CLI:

```text
/project
/project create Обучение причинности
/project show ID
/project step ID
/project pause ID
/project resume ID
/project auto ID on
/project auto ID off
/project retry ID
/project cancel ID
/project from-goal GOAL_ID
/project start ID
/project extend ID Новый вопрос по теме
/project revise ID Уточнённая тема
```

`step` выполняет ровно одно действие. `start` принимает предложение; `resume`
продолжает приостановленный проект. `retry` явно разрешает повтор ошибочного шага,
не более трёх попыток. При несовпадении содержимого существующего файла запись
останавливается; изменённый файл автоматически не перезаписывается.

`extend` добавляет этап только к завершённому проекту, сохраняя предыдущие результаты.
Всего разрешено до 32 этапов. `revise` меняет тему ещё не начатого текущего этапа,
сохраняет историю пересмотра и ставит проект на паузу. Начатый этап нельзя незаметно
переименовать после сбора свидетельств. Это первое расширение длительных проектов;
универсальный планировщик произвольных задач и автоматический пересмотр ценностей
по результатам этих файлов пока не реализованы.

## Фон и восстановление

Самостоятельные шаги включаются отдельно через `auto ID on` и выполняются только
у активного проекта. Нужны работающий неприостановленный когнитивный цикл,
отсутствие текущего диалога, не менее пяти минут без сообщений и энергия от `0.35`.
Между действиями одного проекта проходит минимум минута. Приоритет получает проект
выбранной активной цели, далее — дольше ожидающие проекты. Неактивная связанная цель
приостанавливает проект перед следующим шагом. Для ручного действия нужна энергия `0.08`.

Пределы по умолчанию: четыре новых проекта, 24 действия и три самостоятельных
действия в сутки. `DIGITAL_CHILD_PROJECTS_ENABLED=0` отключает автоматические
предложения и продвижение проектов; ручные команды остаются доступны.

Шаг сохраняется как `running` вместе с подготовленными аргументами до внешней записи.
После перезапуска его можно продолжить ручным `step`; проект с включённым `auto`
продолжает планироваться в простое. Повтор записи использует то же имя и содержимое.
Уже существующий идентичный файл принимается; отличный или частично записанный файл
блокирует шаг. Файловая система и SQLite не образуют общей транзакции: это явное
восстановление после прерывания, а не гарантия единственной физической записи.

Краткие сводки хранятся отдельно от полных результатов, чтобы обновления интерфейса
и планировщик не перечитывали содержимое всех заметок. В Qt есть кнопка «Проекты»,
прогресс в «Развитии» и связанные записи в журнале. Контекст ответов и инициативы
содержит краткое описание следующего шага или причины блокировки.

## Данные и доступ

Файлы находятся в `projects/<subject-id>/` рядом с базой. Имя создаётся из внутренних
ID проекта и шага. Произвольный путь от пользователя не принимается; существующие
символические ссылки и Windows junction на пути отклоняются; файл ограничен 64 КБ.
Это ограниченный локальный исполнитель, не изоляция от другого процесса ОС, который
может одновременно изменять рабочие файлы.

Поиск получает только общие эпизоды и воспоминания указанного собеседника. Предложения
самого агента первоначально используют только общую память. При принятии такого
предложения из чата проект закрепляется за текущим собеседником. Сброс личности
очищает записи проектов в базе; созданные файлы на диске автоматически не удаляются.

HTTP-доступ защищён существующим `X-Operator-Token` как для записи, так и для чтения
полных проектов:

- `GET /v1/projects` — краткие сводки;
- `GET /v1/projects/{id}` — полный план с результатами;
- `POST /v1/projects` — `{ "title": "Тема", "person_id": "api-user", "goal_id": null }`;
- `POST /v1/projects/{id}/step` — одно действие;
- `POST /v1/projects/{id}/actions` — `{ "action": "auto", "text": "on" }` и другие действия.

Связанные с проектами события HTTP-журнала скрыты без токена; просмотр их подробностей
также требует токен, включая связанные полные результаты проекта.

API предназначен для доверенного оператора, а не для нескольких независимых
авторизованных пользователей. Существующие диагностические HTTP-маршруты проекта
не превращены этим изменением в полноценную систему пользовательских прав.

Новые данные используют существующее хранилище feature records. Выполнены статические
проверки; тесты, реальная LLM и динамическое восстановление после аварии не запускались.
