# Инициатива, время и отложенная проверка фактов

Продолжение запросов об инициативе и офлайн-режиме сохранено в ветке
`developmental-psychology-windows`. Развитие определяется опытом; время влияет
на отсутствие контакта, паузы и бюджеты, не начисляя DEU.

## Самостоятельные реплики

`InitiativePlanner` выбирает продолжение дискуссии, тему личного интереса или
восстановление контакта. Каталог тем учитывает семь стадий с плавным переходом
между ними, черты характера, знакомство с темой и приобретённые интересы.
Направление дискуссии может быть исследующим, самостоятельным возражением,
связью с отношениями или рефлексией о последствиях.

`InitiativeRuntime` отделён от дешёвого когнитивного цикла. Новое сообщение человека,
пауза, выключение инициативы, закрытие и сброс отменяют устаревшую генерацию.
Самостоятельная реплика, её дневной бюджет и состояние контакта сохраняются
одной транзакцией. Повтор последних реплик не доставляется.

По умолчанию: 120 секунд до продолжения дискуссии, час до предложения интереса,
900 секунд между инициативами, 5 реплик в сутки UTC и максимум 2 без ответа.
Обычное продолжение останавливается после первой неотвеченной инициативы;
повторное восстановление контакта требует суток. Реплики о результатах проверок
также используют общий бюджет, паузу, разрешение контакта и лимит безответных сообщений.
Фразы «не пиши мне первым» запрещают инициативу для этого человека,
«можешь писать» разрешает её снова, «я занят» даёт 4 часа тишины,
«пока» и «спокойной ночи» — 12 часов.

Приложение или API должны работать. Нет отправки в мессенджеры и работы при
закрытом процессе. Для API самостоятельные сообщения доступны через историю
`GET /v1/conversation/{person_id}`; push или WebSocket не добавлялись.

## Время и отсутствие

`AgentClock` берёт приблизительное UTC из HTTPS-заголовка `Date` без отправки
переписки. По умолчанию используется `https://www.wikipedia.org/`, тайм-аут 3 секунды,
повтор раз в час. Сохраняются последняя успешная сверка, поправка к системным часам
и время двух запусков. Пока нет связи, используется последняя поправка;
между сверками время движется по монотонному таймеру.

После 24 часов от последнего сообщения человека сила нехватки общения плавно
растёт по `1 - exp(-overdue_hours / 24)`, с поправками на привязанность, характер
и отношения. Отрицательный интервал обнуляется. Повторные heartbeat не складывают
один и тот же эмоциональный штраф. Скука не вызывает развитие сама по себе.

Эта схема не заменяет точный NTP. Если системные часы неверны и нет сети,
реальная длительность перерыва неизвестна. Переписка упорядочена по поступлению,
поэтому коррекция UTC не делает старое сообщение последним.

## Офлайн-факты и проверка при возвращении сети

Каждое распознанное фактическое утверждение сохраняется с собеседником,
исходным сообщением и породившей проверку стратегией. Субъективное мнение
не становится внешним фактом. Офлайн-поиск оставляет задачу в SQLite.
При открытии старой базы импортируются до 500 ещё не учтённых утверждений;
уже завершённые сохранённые исследования не применяются к доверию повторно.

`VerificationRuntime` выполняет по одной проверке, вне блокировки диалога.
Он стартует вместе с циклом или после сообщения, которому нужна фоновая проверка.
Повторные попытки ограничены 8 в сутки UTC; пауза растёт от 5 минут до суток.
Нулевой лимит отключает новые автоматические попытки. Пауза цикла, `manual`,
`DIGITAL_CHILD_AUTO_RESEARCH=0` и отключённый поисковый провайдер также их запрещают.
Поиск сам определяет доступность источников: сбой сервера времени не запрещает поиск.

Успешная оценка сохраняет свидетельства, изменение доверия и завершение задачи
одной транзакцией с вложенными savepoint. Сбой и неясный результат не снижают доверие.
После подтверждённого источниками противоречия агент может вернуться к прежней фразе,
привести ссылки и предложить обсудить основания. Это ограниченная реплика из
сохранённых результатов, а не свободная генерация обвинения в обмане.
Намерение человека не считается доказанным одним неверным утверждением.

Локальные Ollama/llama.cpp с уже скачанной моделью работают без интернета.
При недоступности языковой модели диалог сохраняется, но ответ алгоритмический
и ограниченный. Для семантической оценки источников нужна работающая LLM;
алгоритмический fallback оставляет неподтверждённый результат неясным.

## Управление и диагностика

| Назначение | Команда | HTTP |
| --- | --- | --- |
| Инициатива | `/initiative`, `/initiative on`, `/initiative off` | `GET /v1/initiative` |
| Изменить инициативу | те же on/off | `POST /v1/initiative/{true\|false}` |
| Личные темы | `/interests` | `GET /v1/interests` |
| Время | `/time` | `GET /v1/time` |
| Проверки | `/verifications` | `GET /v1/verifications?limit=20` |

Изменение инициативы через HTTP требует `X-Operator-Token`, совпадающего с
`DIGITAL_CHILD_OPERATOR_TOKEN`. В окне вкладка «Интересы» показывает темы,
состояние инициативы, источник времени и число непроверенных фактов.
Все переменные окружения перечислены в корневом `.env.example`.

Хранилище получает таблицы `runtime_state` и `deferred_verifications` при открытии.
Сброс личности удаляет проверки вместе с её историей; поправка часов остаётся
настройкой среды. Используйте один активный процесс агента на файл базы.

По прежнему указанию пользователя тесты не добавлялись и не запускались.
Статические проверки не подтверждают поведение с настоящей LLM или на Windows.
