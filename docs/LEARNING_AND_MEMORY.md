# Память, обучение и история развития

Реализованы все семь пунктов следующего расширения. Они используют существующие
эпизоды, личность, проверки источников и таблицу `feature_records`. Новых зависимостей
и внешних исполнителей нет. Долгосрочные личные проекты остаются отдельным будущим этапом.

## 1. Ассоциативная память

`AssociativeMemory` индексирует эпизод, собеседника, смысловые понятия, связанные
убеждения, решение и наблюдаемые последствия. Поиск сочетает общие понятия и основы
слов, учитывает редкость признаков, важность и архивный статус. Например, сообщения
«я устал» и «нужен перерыв» связываются через понятие нагрузки без совпадения слов.
Найденные эпизоды входят в контекст ответа и усиливают соответствующие эмоциональные
воспоминания в пределах прежних ограничений психологии.

При доступной настроенной LLM можно дополнить локальный словарь смысловыми метками.
Это отдельный структурированный запрос с прежним тайм-аутом анализа. Бюджет по умолчанию
20 запросов в сутки UTC; повторный текст использует кэш до 128 записей текущего процесса.
При ошибке, отключении или исчерпании бюджета остаются локальные признаки.
Метки служат только поиску и не становятся доказательствами или убеждениями.

Поиск рассматривает 500 последних индексированных эпизодов. Записи сохраняются в SQLite;
индекс не является неограниченным векторным хранилищем. При первом запуске расширения
без обращения к LLM индексируются до 100 последних наблюдений вне диалога.
Старые разговоры без надёжной привязки к человеку автоматически не импортируются.
Новые диалоги индексируются с явным `person_id`; поиск исключает индексы других людей.
Прежняя память продолжает работать отдельно.

## 2. Самооценка компетентности

`CompetenceModel` хранит число наблюдаемых попыток, результаты, последние 12 исходов
и среднюю квадратичную ошибку предварительной оценки успеха (Brier score).
Малое число наблюдений сохраняет неопределённость. Последние исходы позволяют
пересматривать уверенность при смене правил. Повторная обработка одного результата
не добавляет вторую попытку; записи сохраняются после перезапуска.

Для каждого вида эксперимента измеряется точность прогноза наблюдаемого результата.
Для `finding_evidence` — получение свидетельств с содержательным суждением, независимо
от того, подтвердилось исходное утверждение или было опровергнуто. Недоступность сети
не считается ошибкой знания. Неизмеренные темы помечаются отсутствием наблюдений.

Оценки входят в контекст и выбор ответа: неоднозначность требует уточнения,
а вопрос о закрытой среде при малом опыте вызывает предложение небольшого эксперимента.
Они также влияют на ранжирование следующего опыта. Отказ и защищённые решения ядра
сохраняют приоритет. Оценка навыка в симуляции не объявляется вероятностью истинности
любого ответа языковой модели.

## 3. Модель знаний собеседника

`InterlocutorMemory` отдельно для каждого человека сохраняет прямые сообщения
о понимании, выраженные взгляды, предпочтения примеров и счётчики уже данных объяснений.
Сведения включаются в ответы и инициативу, чтобы учитывать предшествующее объяснение.
Каждая заметка ссылается на исходный эпизод и помечена как сообщение собеседника,
а не проверенный внешний факт. Число объяснений не доказывает понимание.

Сбор прямых сообщений использует локальные эвристики. Модель не выводит способности
или скрытые личные характеристики. Поправки имеют приоритет в следующем контексте.
Можно очистить текущие заметки и предпочтения, оставив новую явную поправку.
Лимиты: 40 заметок, 40 тем объяснений и 20 последних поправок.

## 4. Направленное любопытство

Программа экспериментов выбирает пробел по числу наблюдений, недавним ошибкам,
неопределённости компетентности и ошибке калибровки. Число `expected_information_gain`
является эвристической оценкой полезности, а не вычисленной энтропией модели мира.
Причина выбора сохраняется вместе с попыткой и отображается в интерфейсе.

| Среда | Что меняется |
| --- | --- |
| `balance` | Индивидуальное направление управления |
| `transfer` | Масштаб шага и начального расстояния |
| `noise` | К наблюдению добавляется помеха −1, 0 или +1 |
| `conditional` | Правило зависит от наблюдаемого цвета blue/amber |
| `reversal` | Направление скрыто меняется каждые четыре попытки этой среды |

Начальные среды открывают последующие после двух точных прогнозов. Для условной среды
используется отдельная выученная модель каждого цвета; направление не читается из
скрытого правила при построении прогноза. В шумной среде модель уточняется только
по наблюдаемому движению. Начальные состояния варьируются, но каждый опыт пока состоит
из одного действия.

После заданного числа успешных наблюдений среда исключается из программы; для шума
достаточно шести попыток, поскольку точное предсказание помехи не требуется для остановки.
На одну среду действует предел 20 автоматических учебных попыток в доступной истории.
Ручное выполнение остаётся доступным. Прежние бюджеты (8 всего / 2 самостоятельных
попытки в сутки), часовой интервал, пауза цикла и пять минут без общения сохраняются.
После исчерпания текущей программы самостоятельное повторение прекращается.

## 5. Демонстрации

Человек передаёт наблюдаемый переход, например:

```text
/teach {"kind":"balance","before":3,"action":"right","after":2,"explanation":"Один шаг уменьшил расстояние"}
```

Из разницы состояний извлекается гипотеза направления. Пример принимается только
для одного шага среды (2 единицы в transfer, 1 в остальных). Для conditional дополнительно
нужен `"context":"blue"` или `"context":"amber"`. Объяснение хранится как текст данных.

Пример не даёт DEU и не повышает компетентность. В следующей подходящей попытке
агент использует гипотезу, самостоятельно получает результат симуляции и сравнивает
его с прогнозом. Сохраняются статусы непроверенной гипотезы, единичного совпадения,
переноса между начальными условиями и опровержения. В шуме несовпадение отдельно
помечается как неоднозначное. Исходный пример остаётся доступным.
Неподтверждённая демонстрация может оказаться неверной, в том числе приведённый пример:
направление управления индивидуально для личности.

## 6. Обучаемая саморегуляция

При перегрузке, низкой энергии или неоднозначности выбирается одна из стратегий:
уточнить, разбить задачу, сменить способ решения или предложить паузу.
Выбор учитывает предыдущие применения и сохраняет небольшой приоритет исследования
ещё не опробованных вариантов. Стратегия передаётся речевому модулю и считается
применённой только при наличии соответствующих признаков в итоговом ответе.

Следующая реплика того же человека в пределах часа позволяет сопоставить нагрузку
и продолжение содержательного разговора. При смене темы или истечении часа результат
не засчитывается как полезный исход. Это наблюдаемая связь, а не доказательство
причинного эффекта. Явная обратная связь `helpful`/`unhelpful` имеет больший вес.
Все попытки содержат исходный эпизод и, когда доступен, эпизод последующего наблюдения.

При работающем неприостановленном цикле энергия ниже 0.35 может вызвать восстановление
ресурсов на 0.08: не чаще раза в час и до четырёх раз в сутки UTC. Отдых не даёт DEU.
Это изменение ресурсов модели; никаких внешних действий не выполняется.

## 7. История развития

В Qt добавлена вкладка «Развитие»: оценки навыков, следующий предлагаемый опыт,
дерево событий с показателями до/после. Узел раскрывается до исходного эпизода.
Выбор события загружает содержание эпизодов и доступные свидетельства с ссылками.
Связанные записи опыта, демонстрации или саморегуляции показываются в текущем состоянии.
Выбор и раскрытые узлы сохраняются при обновлении снимков.

Время показано в UTC. События формируются при диалоге, внешнем наблюдении, эксперименте,
отложенной проверке, отдыхе, демонстрации и явных исправлениях/оценках.
История содержит фактические изменения стадии, DEU, характера, ценностей, настроения,
привычек, убеждений, навыков и доверия. Это журнал событий ядра, а не цепочка рассуждений LLM.
Он не восстанавливает задним числом изменения, для которых раньше не было журнала.
Окно показывает последние 30 событий; команды и API — до 500.

## Управление

| Команда | HTTP |
| --- | --- |
| `/recall ТЕКСТ` | `GET /v1/associations?query=...&person_id=...` |
| `/competence` | `GET /v1/competence` |
| `/curriculum` | `GET /v1/curriculum` |
| `/teach JSON` | `POST /v1/demonstrations` |
| `/demonstrations` | `GET /v1/demonstrations` |
| `/person-model` | `GET /v1/person-model/{person_id}` |
| `/person-model correct ТЕКСТ` | `PATCH /v1/person-model/{person_id}` |
| `/person-model clear ТЕКСТ` | Тот же PATCH с `clear_notes: true` |
| `/regulation` | `GET /v1/regulation?person_id=...` |
| `/regulation feedback ID helpful` | `POST /v1/regulation/{id}/feedback` с `{"helpful":true}` |
| `/timeline` | `GET /v1/timeline` |
| `/timeline ID` | `GET /v1/timeline/{id}` |

PATCH модели собеседника принимает `{"text":"...","clear_notes":false}`.
Изменяющие HTTP-запросы требуют существующий `X-Operator-Token`.
Сброс личности удаляет новые записи вместе с прежней историей.

По договорённости тесты не добавлялись и не запускались. Выполняются статические проверки
типов, линтера, компиляции и diff. Точность смысловых меток с настоящей LLM, поведение
окна на Windows и качество обучения в длительном запуске пока не измерялись.
